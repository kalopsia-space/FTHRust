## 1. Uploader (FTHR_Uploader/ + Core glue)

### Process model
- One-shot subprocess, not a daemon. `FTHR_Uploader/uploader_service.py:133-149` reads ONE JSON object from stdin, writes ONE JSON line to stdout, exits 0/1 (`ok` flag). All stdout from the work phase is redirected to stderr (`:143`) so only the final response line is on stdout.
- Argv contract: `<executable> --activation-receipt <path>` (`uploader_service.py:134-136`).
- Core side: `FTHR_UI/core/upload_manager.py:526-562` `_invoke_plugin()` does `subprocess.run([receipt['executable'], '--activation-receipt', activation.json], input=json.dumps(request), capture_output=True, timeout=600)`; takes the LAST non-empty stdout line as the response (`:549-557`); non-dict/invalid JSON -> `{'ok': False}`. `CREATE_NO_WINDOW` only on win32 (`:537-538`).
- Request format: `{'action': ..., 'activation_id': <receipt token>, **payload}` (`upload_manager.py:532-536`). Actions: `upload` (payload `path`, `allowed_roots`, `clips_root`; `upload_manager.py:812-818`), `test_connection` (`config` dict; `:928-931`), `sftp_save` / `sftp_forget` (`config`; `:921-926`). Response: `{'ok', 'message', ['upload_info']}` (`uploader_service.py:117,126,129,146`).
- Clip path authorisation: service resolves `path` with `strict=True` and requires it under one of `allowed_roots` (`uploader_service.py:90-100`); Core computes roots = clips dir + `imported_clip_folders` (`upload_manager.py:509-524`).
- Core-side queue: worker thread + `queue.Queue`, QTimer interval scans, write-settle 30 s, in-flight/local-mutation sets (`upload_manager.py:60,165-199,564-600,670-720,829-878`). Modes: `immediate|interval|manual` (`:77-79`). Auto-compress path `_compress_then_upload` writes to `<clips>/Shared/<stem>_<provider>_upload_<HH-MM-SS>.mp4` and aliases history (`:720-802`).

### Activation / consent-install flow (receipt-gated)
- Bundle lives at `plugin-packages/<filename>` next to `_MEIPASS` / frozen exe / repo root (`upload_manager.py:241-254`). `_BundleSpec` (`:104-128`) is hard-wired to **Windows values**: `filename='FTHR-Uploader.fthrplugin'`, `entrypoint='FTHR Uploader.exe'`, install root `%LOCALAPPDATA%/FTHR Clips/plugins/uploader` (`:51-55`), receipt `activation.json`.
- `_inspect_bundle` (`:256-287`): bundle sha256 must equal `EXPECTED_UPLOADER_BUNDLE_SHA256` from `FTHR_UI/core/uploader_bundle_manifest.py:7`; empty constant -> "development build not bound"; reads `manifest.json`, `TERMS_OF_SERVICE.txt`, `PRIVACY_POLICY.txt` from the zip; entrypoint must match spec (`:284`).
- `_activate_bundle` (`:328-417`): zip entry set must equal exactly `{manifest.json, TERMS, PRIVACY} ∪ manifest.files[].path` (`:347-366`); zip-slip checks (`:353-356,370-374`); per-file sha256 from manifest (`:378-382`); staged `payload/` dir `os.replace`d to `<install_root>/<plugin_version>/` (`:385-395`); receipt written atomically (`:403-414`) with `plugin_id, plugin_version, terms_version, privacy_version, accepted_at, activation_id (token_urlsafe(32)), bundle_sha256, executable, executable_sha256, settings_file`.
- Service re-validates receipt every run (`uploader_service.py:41-65`): plugin id/version, terms/privacy versions, `activation_id` equality, **sha256 of its own `sys.executable`** vs receipt, and reads `settings_file` to require `upload_enabled` for network actions.
- `is_plugin_installed` (`upload_manager.py:294-326`): receipt present, versions match, bundle hash matches, executable exists and hashes correctly, legal versions current.
- UI: `FTHR_UI/ui/upload_settings_widget.py:524-567` — enabling the checkbox when not installed shows `_legal_install_dialog` (`:88-157`, two checkboxes, both required), then `activate_plugin(TERMS_VERSION, PRIVACY_VERSION)` (`upload_manager.py:419-452`); then per-provider consent `_ensure_provider_ready` (`:577-589`) -> `_provider_consent_dialog` only for Catbox (`:159-213`, link `https://catbox.moe/legal.php`, `:55`). Test `tests/test_uploader_plugin_boundary.py:203-211` asserts the settings widget is the only `activate_plugin` call site.
- Settings: `~/.fthr/uploader/settings.json` (`upload_manager.py:57`), defaults at `:64-87` (provider, catbox_userhash, server url/auth header, sftp_*, mode/interval, auto_compress/auto_delete, accepted versions). Legacy keys migrated from core settings (`:89-97,480-502`); `lustful_*` keys dropped (`:230`).

### Providers (FTHR_Uploader/upload_runtime.py, sftp_provider.py)
- Provider ids: `catbox`, `custom` (aliases `own_server`/`your_server`), `sftp` (`upload_runtime.py:101-107`, `uploader_service.py:68-74`). Consent: Catbox requires `catbox_legal_accepted_version == 'catbox-legal-2021-03-06'` (`uploader_service.py:21,81-83`).
- Retry: 3 retries with delays 5/15/45 s for HTTP providers; SFTP never retried (`upload_runtime.py:23,53`).
- **Catbox**: `POST https://catbox.moe/user/api.php`, multipart fields `reqtype=fileupload`, optional `userhash`, file field `fileToUpload` (`:20,115-125`); response must be 2xx and start with `https://`; 200 MiB hard limit (`:24-26,41-50`); `HEAD` for connection test (`:92-99`). HTTPS enforced (`:207-208`).
- **Custom server**: multipart `POST <upload_server_url>` with file field `clip`, optional `Authorization: <upload_auth_header>` (CR/LF rejected, `:265-269`), http or https allowed (`:138`), bare host gets `https://` prefix (`:253-262`); response parsed as JSON `{url|raw_url}` or bare URL, first 4096 chars kept (`:140-162`); `HEAD` test accepts any HTTP status as reachable (`:164-179`).
- Multipart writer is hand-rolled over `http.client` with fixed boundary `FTHRClipBoundary8f61d4`, streamed 1 MiB chunks, `User-Agent: FTHR-Clips/Desktop-Uploader`, 120 s timeout (`:195-250`).
- **SFTP (paramiko 4.0.0)**: password auth only, `allow_agent=False, look_for_keys=False` (`sftp_provider.py:186-189`); legacy algorithms disabled (`:190-197`); 8 s timeouts, channel 20 s (`:189,200`). Host identity: explicit `SHA256:<43 base64>` pin via `_PinnedKey` (`:72-79,131-138`) OR `~/.ssh/known_hosts` + `~/.fthr/uploader/known_hosts` with `_UnknownHost` reject (`:141-152,181-185`); verified pinned keys appended to the FTHR known_hosts atomically (`:154-169,204-211`). Upload: random name `fthr-<32hex><ext>` written as `.part` with mode 0600, size-verified, renamed, size re-verified, chmod 0644 only if public mapping enabled (`:233-268`). Returns `sftp://` URL and optional public HTTPS URL (`sftp_public_base_url` validated `:27-40`).
- **Password/keyring**: `_vault()` hard-fails on non-win32 ("Saved SFTP passwords currently require Windows Credential Manager", `:83-88`); Linux bundle nevertheless freezes `keyring.backends.SecretService`, `secretstorage`, `jeepney` (`tools/build_linux_uploader.py:43-48`). Credential key = `FTHR Clips/SFTP/<sha256(host\0port\0user)>` (`:91-94`). Transient password accepted in request `config.sftp_password` (`:117-120`).
- VaultScope partner path in the UI maps to provider `sftp` with `sftp_provider_name='VaultScope'`, host must be `sftp.vaultscope.de`, JSON pasted from clipboard (`upload_settings_widget.py:627-646,703-735`; `docs/vaultscope-partner-2026-10-14.md`).

### Linux build of the uploader and why it is separate
- `build_linux.sh:166-175` runs `tools/build_linux_uploader.py --python $PYTHON_BIN`, which: checks `requirements-uploader.txt` pins are installed (`build_optional_uploaders.py:94-127`), PyInstaller `--onefile --console --name FTHR-Uploader` with hidden imports (`build_linux_uploader.py:142-152`), unpacks every ELF member of the one-file exe to `build/optional-uploader-linux/payload-elf` for the glibc gate (`:71-90,158`), seals `plugin-packages/FTHR-Uploader-linux.fthrplugin` (`:35,93-124`), writes the Linux hash into the Core manifest (`:161`). `FTHR_linux.spec:10-14,159` refuses to build without that bundle and ships it under `plugin-packages/`.
- Rationale (stated): "FTHR Clips Core contains no provider upload client" (`PRIVACY_POLICY.txt:6-9`, `upload_settings_widget.py:538-540`); network code, paramiko (LGPL-2.1) and its crypto deps are kept out of Core, consent-gated, hash-sealed; `requirements-uploader.txt:1` "do not add SSH clients to Core". Licence inventory for the plugin is separate (`licenses/optional-uploader/*`, `THIRD_PARTY_NOTICES.md:207-239`). The isolation is a privacy/consent boundary more than a licence necessity (paramiko LGPL would be fine dynamically in a GPLv3 app).

## Separate binaries vs. fold into the main Rust app
- **Must stay a separate binary:** the native capture engine (`FTHRcapture_linux/build/FTHRclips`, shared-memory IPC; out of scope here) and `libFTHRPlaybackMixer.so` if it remains C++; bundled `ffmpeg`/`ffprobe` CLIs + 7 LGPL FFmpeg `.so` (must remain dynamically linked, replaceable, `$ORIGIN` RPATH).
- **Should stay a separate consent-gated binary (policy, not licensing):** the uploader. Its privacy/terms text, bundle sealing, receipt+activation_id+self-hash protocol and "Core contains no upload client" statement all assume a separately shipped, dormant executable. A Rust `fthr-uploader` crate (own binary in the AppImage, same stdin/stdout JSON contract) keeps those documents true; folding it into the main app requires rewriting the privacy policy, TPN §207-239, README architecture text and the consent dialog copy.
- **Fold into the main Rust app / drop:** Hardware ID service (dead; drop entirely), `repair_stripped_elf.py` (PyInstaller-specific; drop), Qt runtime manifest and Qt-related gate checks (drop), PyInstaller spec (replace with cargo build + AppDir assembly), the Python-only verify scripts (`verify_exception_handling`, `verify_engine_response_contract`, Qt/PySide checks) → replace with clippy/deny rules; keep as scripts (shell/Python in `tools/`): `fetch_third_party.py --ffmpeg-linux/--appimagetool-linux`, `verify_release_licenses.py` (FFmpeg/asset/licence parts), `verify_linux_glibc.py`, `verify_version_consistency.py` (point at `Cargo.toml` version), `verify_shared_memory_contract.py` (point at the Rust struct), `scan_repo_hygiene.py`, `package_source.py`, `linux_*_report.sh`, `generate_release_assets.py`.
