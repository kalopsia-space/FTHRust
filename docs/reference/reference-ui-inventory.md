# FTHR Clips UI inventory (Linux/Wayland) — for a pixel-faithful Rust/egui rewrite

Source checkout: `scratchpad/repo` (branch snapshot, Oct 2026). All pointers are `path:line` relative to the repo root. Windows-only modules are listed once as "omitted" and not described. The Python UI is PySide6 (Qt 6 widgets + a little Qt Quick); `FTHR_UI/main.py` is 14,238 lines and owns the main window, all top-bar popups and the whole Settings page; `FTHR_UI/ui/*` holds the library grid, the clip editor, dialogs and style tokens; `FTHR_UI/core/*` is non-UI logic.

Omitted (Windows-only): `core/windows_autostart.py`, `core/windows_dpi.py`, `core/windows_microphone_devices.py`, `core/windows_monitor.py`, `core/third_party_keyboard.py` (external keyboard-overlay capture; the Visuals page "Keyboard overlay" block is dead on Linux), `ui/frameless_window_windows.py` (WM_NCHITTEST hit testing; `ui/dialogs.py:31` imports its `start_system_move` but only calls it on win32), `ui/capture_card_process.py --card-process` relaunch path is used on both platforms but the frozen-exe relaunch is Windows-specific, manual "Record" button (`main.py:3853-3864`, disabled on non-win32), system tray (`main.py:3648-3651` returns False off win32), controller bindings (`main.py:2759`, cleared/disabled off win32 at `main.py:3022-3026`).
Omitted (X11-only): `core/x11_monitor.py`.

### 5.1 Capture bridge (UI <-> native engine), `FTHR_UI/core/capture_bridge.py`

- Transport: a single POSIX shared-memory segment `/dev/shm/FTHR_SharedMemory_v4` (capture_bridge.py:127,164), created by the engine (`FTHRcapture_linux/src/main.cpp:127`), opened read-write and `mmap`ed by the UI (capture_bridge.py:166-204). Mapping is refused while `is_initialized` is false (:206-214). Windows uses `c_wchar*256/512` + kernel32 mappings — omitted.
- Commands (`CommandType`, :20-32): NONE 0, START_RECORDING 1, STOP_RECORDING 2, SAVE_CLIP 3, SET_RESOLUTION 4, SET_QUALITY 5, SET_FRAMERATE 6, SET_HOTKEY 7, SET_TARGET_WINDOW 8, GET_STATUS 9, RECONFIGURE_ENCODER 10, SHUTDOWN 11. - Wire protocol rule: write payload fields first, `ui_command` LAST (engine polls `ui_command` every 20 ms and clears it to NONE before dispatch, main.cpp:182-187); engine likewise writes `engine_string`/params before `engine_response`; only the UI clears a consumed response to NONE (shared_memory.h comment; `tools/verify_engine_response_contract.py` is a source gate for this ordering).
- Commands the UI actually sends on Linux:
  - `save_clip(path, duration)` (:292-324): UTF-8 path truncated to 1023 bytes into `ui_string`, `ui_param1=duration`, then `ui_command=SAVE_CLIP`. Returns submission success only.
  - `pause_recording()` -> STOP_RECORDING (:327); `resume_recording()` -> clears `ui_string` to b'' then START_RECORDING (:333-342).   - `set_encoder_config(codec_pref, preset)` -> writes `cfg_codec_pref`, `cfg_preset` (clamped 1..7) then RECONFIGURE_ENCODER (:516-528). Engine re-opens the encoder in place (main.cpp:235-251).
  - `start_manual_recording`/`stop_manual_recording` are hard-disabled on Linux (`sys.platform != 'win32' -> False`, :344-361). The Linux engine refuses START_RECORDING with a non-empty path via MANUAL_RECORDING_ERROR + engine_string "Manual recording is not available on Linux yet." (main.cpp:28-50).
  - Never sent: SET_RESOLUTION/SET_QUALITY/SET_FRAMERATE/SET_HOTKEY/SET_TARGET_WINDOW/GET_STATUS (engine acks them with STATUS_UPDATE, main.cpp:253-276).
- Status read (`get_status()`, :486-514) returns dict: `connected, is_recording, frames_captured, nvenc_active, capture_health_flags, capture_generation, content_sample_sequence, content_suspicious_streak, content_luma_mean, content_luma_variance, capture_failure_detail` (the latter = `engine_string` only when BACKEND_FAILED is set, Linux only). Also `get_active_codec()` (:530), `get_active_preset()` (default 4, :540), `get_audio_mappings()` (JSON in `active_audio_mappings`, always `{}` on Linux, :549), `is_multiband_active()` (always false on Linux, :564).
- Save response channel (single reader): `peek_save_response()` returns `('started'|'saved'|'error', detail)` without consuming; SAVE_STARTED is acknowledged locally (`_save_acknowledged_layout`) because completion may overwrite it between peek and consume; `consume_save_response(kind)` clears only terminal results (:386-441). Manual-recording responses have their own peek/consume (:443-473) so they never steal save events.
- Generations: two independent counters. (1) *process generation* `_engine_gen` in main.py, incremented on every `start_engine`/`stop_engine`/crash detection (main.py:5536, 6069, 8581); every async callback checks `_owns_engine_attempt(gen, process, bridge)` (main.py:5414) so a stale worker can never touch a replacement engine. ### 5.3 Clip save flow (UI side, main.py:6721-7110, `core/save_state.py`)

- Preconditions: not in manual-record transition; bridge connected (else Error 002 `CAPTURE UNAVAILABLE`); `evaluate_save_admission(snapshot, seconds)` (capture_health.py:381-401) rejects STOPPED/FAILED/RECOVERING with Error 013 `CLIP NOT SAVED` ("Capture is recovering…" / "Capture is not receiving new frames…"); 1 s debounce and single-flight via `SaveStateMachine.is_busy()` (busy -> status `SAVING` for 1 s, `_show_save_busy_feedback`).

- `_pump_save_responses()` first (consume any stale result), then `bridge.save_clip`; on acceptance `SaveStateMachine.submit()` with `mic_end_time` (monotonic instant used by the mic post-mux), capture card shows the clip-captured overlay immediately, status `SAVING`, `_save_poll_timer` 50 ms starts (:3511-3512, :6846-6896). State machine (save_state.py:14-27, :122-127): REQUESTED -> WAITING_FOR_ACK -> ENGINE_ACCEPTED (SAVE_STARTED) -> ENGINE_COMPLETED/ENGINE_FAILED; ack timeout 1.0 s, completion timeout 60 s -> TIMEOUT_NOTICE (status `SAVE SLOW…`, not a verdict; late CLIP_SAVED is still accepted via the 500 ms poll, :6988-6997, :7109). FAILED -> Error 015 `CLIP WAS NOT SAVED` with engine detail, status `SAVE FAILED` for 3 s. ### 5.4 Capture health (`core/capture_health.py`) and recovery (`core/error_recovery.py`)

- Engine flags (IntFlag :15-24): ACTIVE 1, RECOVERING 2, BACKEND_FAILED 4, CONTENT_SUSPECT 8, PAUSED 16, RECONFIGURE_REQUIRED 32 (the last is Windows-only; the Linux header stops at PAUSED).
- `CaptureHealthMonitor.observe(connected, frame_count, engine_flags, generation)` (:113-272) is a pure state machine run from the 500 ms poll. Thresholds: `WARNING_AFTER_S=3.0` -> DEGRADED ("frame progress delayed"), `STALLED_AFTER_S=8.0` -> STALLED (one `request_recovery` per incident; budget restored after 30 s healthy, `RECOVERY_BUDGET_RESET_S`), BACKEND_FAILED -> FAILED, RECOVERING flag -> RECOVERING, PAUSED -> DEGRADED, CONTENT_SUSPECT with fresh frames -> CONTENT_SUSPECT, disconnect -> STOPPED, new generation -> INITIALIZING (re-baseline count). Snapshot fields: `state, previous_state, reason, changed, request_recovery, seconds_since_progress, fresh_buffer_seconds`; `save_allowed` = not STOPPED/FAILED/RECOVERING. `request_recovery` is only logged on the UI (engine owns automatic recovery, main.py:8917-8920).
- `sample_bgra_grid`/`ContentSuspicionTracker` (:306-369): 16x9 sparse luma grid, black-like = mean<=8 & var<=6, uniform = var<=2, suspect after 12 consecutive samples (engine parity: capture_engine.cpp:388).
- `RecoveryTracker` (error_recovery.py:24-104): keyed incidents clear only after `MIN_PROGRESS_POLLS=3` progressing polls over `STABLE_FOR_SECONDS=3.0` in the same (process, backend) generation while HEALTHY (CONTENT_SUSPECT allowed only for `capture_backend` incidents). `main.py:_advance_recoverable_errors` (:5436-5497) applies it to `_recoverable_error_incidents` with `recovery_kind` in {`engine_lineage` (needs a newer process generation), `encoder_init` (needs newer generation + hardware_active + HEALTHY), `capture_backend`}; recovered keys are removed from the error bar (`error_bar.remove_by_key`) and emit `application/failure_recovered`.

### 5.8 Playback architecture (definitive)

- **Video + master clock: Qt Multimedia `QMediaPlayer`** (clip_viewer.py:5386-5402, basic_clip_viewer.py:22). On Linux Qt's own FFmpeg media plugin decodes (main.py:84-89 sets `QT_MEDIA_BACKEND=windows` only on win32; clip_viewer.py:166 sets it unconditionally — see suspicious list). - **Audio: three tiers** (clip_viewer.py:7590-7700). (1) Single ordinary track at 1x (or pitch-preserve off) -> `QAudioOutput` of the QMediaPlayer ("qt-container"). (2) Multi-track clips, or any speed != 1 with "Preserve pitch" on -> `FFmpegPlaybackController` (`core/ffmpeg_playback.py:631`): the QMediaPlayer audio is muted and a **native in-process bridge `libFTHRPlaybackMixer.so`** (`FTHRcapture_common/ffmpeg_playback_bridge.{h,cpp}`, C ABI `fthr_playback_open/pull/seek/set_playback_rate/is_eof/source_failed/close`) is loaded with ctypes (search order: `_MEIPASS/engine`, `_MEIPASS`, `<exe>/engine`, `<exe>`, `FTHRcapture_linux/build/libFTHRPlaybackMixer.so`, ffmpeg_playback.py:165-215). One demuxer + one decoder per selected absolute stream index; `pull()` returns canonical 48 kHz float32 stereo with per-source linear gains, equal-power headroom `1/sqrt(active)` and a 0.98 hard limiter applied natively (playback_mix_model.py:9-11, 205-224); pitch preservation uses FFmpeg `atempo` inside the bridge, otherwise Python linear resampling (`_resample_pcm`, rate clamp 0.25..2.0). The `_DecodeWorker` thread (`FTHR-audio-decode`) is the only caller of the bridge; it fills a `BoundedPCMQueue` (max 7200 frames = 150 ms, `_MAX_QUEUED_FRAMES`), block size 1024 frames; a `QAudioSink` (default output device, Float or Int16 48 kHz stereo, 40 ms buffer `_OUTPUT_BUFFER_MS`) pulls from `_AudioPullDevice`; sink is recreated on every play/seek/mix refresh (`_discard_output_buffer`); a 20 ms `_sink_timer` keeps it running. A/V sync: `sync_to_video_position(video_ms)` on every `positionChanged` (clip_viewer.py:7277-7279): drift = estimated audio output position − video; > +120 ms -> suspend sink, resume when drift <= 40 ms; < −120 ms -> seek audio; 750 ms guard after any seek (`_SYNC_*` constants :45-49). Mix changes coalesced to one `refresh_mix(position)` per 40 ms. (3) Fallback to tier 1 if the bridge is missing or fails (`_fall_back_to_container_audio`, :7700).

OpenCV (`cv2.VideoCapture`) is used for first-frame posters, stretch-dialog preview frames and colour compositing (clip_viewer.py:693, 737, 2646, 2996, 3615) — a third decoder.
- `core/media_process.py`: single bounded runner for ffprobe/ffmpeg children: 100 ms polling cancel, default 8 s timeout, stderr tail 32 KiB, background semaphore of 2 plus lanes `proxy` and `timeline` (1 each), terminate -> kill -> reap (0.75 s each); `media_process_snapshot()` reports live/peak counts for diagnostics.
- Playback sources model (`core/playback_mix_model.py`): `ProbedAudioStream(container_index, audio_index, title, audio_mode)`, `PlaybackSource(source_id, display_name, source_type application|system|microphone|track, container_index, audio_index, icon_reference, available, mix_role direct|base|delta, editable, persistent_identity)`; built from the clip's audio manifest sidecar (section 4, `core/audio_manifest.py`) else container streams; ordering application < system < microphone < track; combined captures expose no sliders; "Default Mix" displays as "System Audio"; `ffmpeg_mix_filter` builds the export `volume/amix=normalize=0/volume(headroom)/alimiter=0.98/volume(master)` graph so exports match live mixing.
- `core/audio_mixer.py`: legacy multiband post-mix (N category WAVs -> amix -> aac 192k, `-c:v copy`, replaces the clip in place, 120 s timeout). Dead on Linux (multiband always off).

- `ui/clip_viewer.py:166` does `os.environ.setdefault('QT_MEDIA_BACKEND', 'windows')` unconditionally (main.py:88 is gated on win32). If the UI missed the FAILED poll (e.g. a save response was pending, which holds the flag back, main.cpp:313-324), the user sees a generic "exited unexpectedly (code 0)".

- `postprocess_video_args` hardware set omits `h264_vaapi` (ffmpeg_tools.py:232-234), so every Linux watermark/overlay post-process re-encodes with OpenH264 even when VA-API is active.
- `_save_clip` has dead code: `getattr(self, '_active_game_window', None)` / `pass` (main.py:6843-6844); `crop_profile` is always None on Linux.

### Suspicious / TODO (linux)

- **Screenshots are broken on Wayland by design of the current code**: `main.py:4723` uses `QScreen.grabWindow(0)`; the finished `WaylandScreenshotPortal` is never wired in (a lone `pass` at `main.py:4688` marks the removed branch; `_screenshot_capture_process` is initialised but never set). The rewrite should use the Screenshot portal (or `grim` on wlroots) and keep the `MONITOR_NOT_FOUND` / no-fallback semantics.
- **Automatic game detection is dead on Linux**: `main.py:3437` uses `ForegroundGameDetector` (user32-only); the Linux `GameDetector` (`hyprctl`/`xdotool`) is unused. Even the Linux enumerator only sees fullscreen XWayland windows (no native Wayland toplevels on KDE/GNOME; `xdotool`/`xprop` must be installed).
- `publish_staged_png()` docstring promises a POSIX hard-link publish but the code is a bare `os.rename`, which silently overwrites an existing final name on Linux (`screenshot_save.py:129-145`); the `_01` suffix logic only guards at reservation time.
- `camera_recorder.list_devices()` spawns `ffmpeg -f dshow` on Linux (12 s timeout) before the index probe (`:50-73`); opening indices 0..7 with OpenCV is slow and may grab the camera from another app. No V4L2 names are shown.
- Upload Extension install root is `$LOCALAPPDATA` → `~/AppData/Local/FTHR Clips/plugins/uploader` on Linux (`upload_manager.py:51-55`), `_uploader_spec()` hard-codes the Windows bundle name `FTHR-Uploader.fthrplugin` and entrypoint `FTHR Uploader.exe` (`:116-128`), and `uploader_bundle_manifest.py` carries no `EXPECTED_UPLOADER_LINUX_BUNDLE_SHA256` even though `tools/build_linux_uploader.py` produces `FTHR-Uploader-linux.fthrplugin` with entrypoint `FTHR-Uploader` — the extension cannot be installed from a Linux build.
- Capture card helper forces `QT_QPA_PLATFORM=xcb`/`DISPLAY=:0` (`capture_card_client.py:58-61`); without XWayland the notification process dies silently (sounds are also lost because they are hosted there). `Qt.Tool|StaysOnTop` positioning is not honoured by Wayland anyway — an egui port needs a layer-shell or portal-free approach.
- `GaryOverlay` relies on `WindowStaysOnTop` + `WindowTransparentForInput` full-screen tool window; on Wayland the compositor ignores stacking hints and the overlay may steal the screen or never show.
- Hotkey socket dispatch has no authentication beyond socket mode 0600; any process of the user can trigger `save_clip` etc. Custom-clip actions pass `data in self.hotkeys` so unknown lengths are ignored.
- Portal path: `desktop_triggers` returned by KDE (`"F9, Alt+S"`) are parsed by splitting on `,`; GNOME returns human strings (e.g. `Ctrl+Shift+S`) that `normalize_keyboard_combo` may re-case differently and trigger a spurious "DESKTOP KEPT ITS SHORTCUT" warning (`hotkey_manager.py:884-889`).
- `_hyprland_prefers_socket()` ignores the portal entirely on Hyprland (comment at `:821-830`); users with `xdg-desktop-portal-hyprland` v2 never get the ConfigureShortcuts path.
- Export hardware probe tries `h264_amf` on Linux (always fails, 8 s timeout each on first probe); no `h264_vaapi`/`hevc_vaapi` path.
- `screenshot_target.py:7` imports `windows_monitor` unconditionally (ctypes-free at import, but ties the module to a Windows file).
- `ScreenshotEditor` (`ui/screenshot_editor.py`) is unreachable from `main.py`.
- Mic recorder keeps 900 s of float32 mono (~165 MiB max) and the camera deque 90 s of JPEGs in RAM regardless of the configured clip length.
- `FocusMonitor`/`GameDetector` spawn `xdotool`/`hyprctl` subprocesses every 1-3 s; a Rust port should use the Hyprland IPC socket / `wlr-foreign-toplevel` / KWin scripting instead of shelling out.

6. **Unstyled `QMessageBox`** in four places (`main.py:4462`, `:9032`, `clip_editor_window.py:62`, `:117`) while every other dialog is `FthrDialog`; port should use the FTHR dialog everywhere.
7. **Status label capitalisation**: `_set_status` applies `str.capitalize()` (`main.py:8935`), so engine-provided text and acronyms are lower-cased ("Capture degraded — dark / uniform", "Connecting 2/5"). Reproduce for fidelity or fix deliberately.
8. **Lazy settings categories via `__getattr__`** (`main.py:10109-10144`): attribute access can silently build whole pages (e.g. the Audio page opening a microphone stream); any port should make page construction explicit.
9. **Deferred-timer glue**: 29 `QTimer.singleShot(0, …)` deferrals (23 in `main.py`), e.g. category switch (`:10226`), background pause refresh (`:4163`), native style (`:4175`), game-detection window refresh (`:2179`). They encode ordering assumptions (widget realised before use) that egui's immediate mode makes unnecessary but which must be understood when porting state transitions.
10. **Editor sessions**: only the active editor holds a decoder; parked sessions store `capture_session_state()` + window geometry (`main.py:4454-4476`); restoring a maximized parked editor needs a 32 ms wait for the compositor (`main.py:9729-9731`) — a Wayland-specific timing hack. `_park_active_editor` refuses while an export thread is alive (`:4458-4462`).
11. **Smooth scrolling** uses a 8 ms `PreciseTimer` and `exp(-dt/35)` easing (`ui/smooth_scroll_area.py:16-18`, `:60`); modifier/trackpad events bypass it. The clip grid's hover fade snapshots widgets (`ui/hover_transition.py:131`), which costs a `grab()` per hover and is skipped above 1 Mpx — egui should animate colours directly instead.
12. **Game detection prompt** uses the capture card ("CAPTURE UPDATE") rather than an in-window UI, auto-dismissing after 15 s (`main.py:4989-4999`); the hotkey labels in the prompt are raw binding strings.
13. **Thumbnail cache is keyed by md5 of path+mtime** under `~/.fthr/thumbnails` with a `.meta-v3` sidecar (see §4.6) — must be reproduced or migrated for instant library load.
14. **Screenshot hotkey is broken on Wayland**: `_on_hotkey_save_screenshot` (`main.py:4646-4691`) contains a stray `pass` (`:4690`) where a portal branch evidently was, then always calls `_capture_selected_qt_screen` → `QScreen.grabWindow(0, …)` (`:4709-4730`). `main.py` never imports `core/wayland_screenshot_portal.py` (confirmed by grep; only `tests/test_wayland_screenshot_portal.py` uses it), so on Wayland the saved PNG is black/empty. The port must drive the `org.freedesktop.portal.Screenshot` flow (§6) and keep the `reserve_screenshot_paths`/`ScreenshotEditor` contract.
15. **KWIN ScreenCast picker counted as "CAPTURE STALLED"** (KNOWN_ISSUES.md) — capture health should treat `INITIALIZING` while the portal dialog is open as not stalled.
16. **Fusion + QSS hybrid**: dozens of per-widget stylesheets are regenerated on theme apply via `set_theme_style` factories (`ui/style.py:242-260`); `retarget_widget_font_styles` string-replaces font families inside existing QSS (`:223-239`) — brittle; egui should derive everything from one token struct.
17. **`_NumberSpinBox` letter-spacing 0.8px** (`main.py:626`) is the only non-zero tracking besides `GameCropDialog` (2px, `ui/game_crop_dialog.py:160`) — keep for fidelity.
19. **Game detection is dead on Linux**: `MainWindow` instantiates the Windows `ForegroundGameDetector` (`main.py:3437`), whose `available` flag is False without user32 (`core/game_detector.py:761`) so `start()` returns False (`:782-784`); the Linux `GameDetector` (`hyprctl`/`xdotool`, `core/game_detector.py:112`) is only exercised by tests. The Game-detection popup, prompt card, crop profiles and focus pause therefore never fire on Wayland (details §6).
18. **Capture-card process** reads theme/settings files itself (`ui/capture_card.py:337-345`, `SettingsManager()` per show) — a second reader of `settings.json`/`theme.json`; concurrent writes rely on atomic replace (§4.1).
