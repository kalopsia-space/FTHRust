# FTHRust audit, 2026-10-31

Whole-project review of `main` at `75d61ad` (v2.0.0-alpha.2) plus the uncommitted uploader-terms change.

**How it was done.** I ran the automated checks myself. Ten parallel reviewers each read one area in full (engine+ipc, media capture, Wayland+portal, playback/export, core, uploader, UI services, editor/library/overlay, settings/popups/widgets, CI/packaging/docs). I then checked the top claims against the code.

**Verification labels used below:**

| Label | Meaning |
|---|---|
| **observed** | Seen at runtime: on the uidrive bench, or reproduced. |
| **measured** | Numbers from a real run. |
| **verified** | I re-read the cited code (and the dependency source where it matters) and the claim holds. |
| **reported** | A reviewer's static finding that I did not re-check. Treat it as likely, not proven. |

## State at a glance

- **GitHub:** no open or closed PRs, no issues. The last 10 CI runs on `main` are green. Two pre-releases are published (alpha.1, alpha.2). The repo is **public**.
- **Tests:** `cargo test --workspace` gives 1007 passed, 1 failed, 8 ignored. The failure is in the uncommitted change (see [WIP](#the-uncommitted-uploader-terms-change)).
- **Lints and checks:**
  - `cargo clippy --all-targets -D warnings` is clean.
  - `cargo fmt --check` fails, also in the WIP.
  - `cargo deny check` passes (advisories, bans, licences, sources). Warnings: yanked `clipboard-win 5.4.1` (Windows-only, via arboard) and 4 unused licence allowances.
- **Flaky test:** `daemon::shutdown_waits_for_a_save_in_flight` failed 6 of 40 isolated runs (**observed**). It is a real product race; see E2.
- **Pedantic clippy** gives about 4,500 warnings, mostly casts and docs. The useful subset is folded into the findings below.

## Tier 2: performance that hurts while a game is running

| Finding | Where | Label |
|---|---|---|
| **Gary overlay deep-copies its image every tick.** `images[which].clone()` copies a `ColorImage` (`Vec<Color32>`, up to 2048² = 16.8 MB) every 33 ms while Gary shows, though it's needed only when the texture slot is empty. That is about 500 MB/s of memcpy plus a 16.8 MB mmap/munmap per tick. Clone only inside `get_or_insert_with`, or hold `Arc<ColorImage>`. The image is also loaded at 2048 px for an on-screen size of about 820 px at 1080p. | `crates/fthrust-ui/src/overlay/gary.rs:218-227,120-131` | verified |

| **The overlay builds a new Vulkan instance, adapter, device and renderer for every card and every Gary appearance.** Keep them for the thread's lifetime; recreate only the layer surface. This also fixes Tier 1 #8. | `crates/fthrust-ui/src/overlay/surface.rs:76-136` | verified |
| **Every service event repaints the whole UI.** `Outbox::send` always calls `request_repaint()`. Health status arrives about once a second forever, SaveProgress once per MiB (hundreds per save), and Toplevels on any window-title change. The result is GPU work at ≥1 Hz behind the game. Add a `send_quiet` that only wakes the loop. | `crates/fthrust-ui/src/services/mod.rs:237-243` | verified |
| **Wayland waits busy-spin their last sub-millisecond.** `PollTimeout` is built from `as_millis()`, which truncates, so the final <1 ms becomes a `poll(0)` loop. Round up instead. | `crates/fthrust-wayland/src/dispatch.rs:286-287` | verified |

| **CPU colour conversion is single-threaded.** This is the NVENC, QSV, AMF, software and VA-API-fallback path. ## Tier 2: correctness, medium

**Engine and capture**

- **E2 (flaky test).** The shutdown save-wait can drop `SaveResult`. The save thread sends the result and then clears `busy`; the wait loop exits on `!is_busy()` while the event is still crossing the forwarder thread. Fix: track the in-flight request id and wait for its result. `daemon.rs:473-490`, `save.rs:76-81`. **observed** (6/40).
- **Disk replay buffer silently reverts to RAM** after any encoder reopen or geometry change: `clear()` resets `Inner` and drops the disk store. `crates/fthrust-media/src/ring.rs:299-303`. **verified**.
- **The capture card eats clicks** in the game's top-right corner. `Placement::Corner` sets no input region; Fullscreen does. `crates/fthrust-wayland/src/layer_shell.rs:241-246`. **verified**.
- **Flipped90 and Flipped270 un-transforms are swapped** relative to the code's own Rot90 convention, so flipped outputs come out rotated 180°. `crates/fthrust-wayland/src/frame.rs:308,310`. **verified** (by derivation).
- **Reported, not re-checked:**
  - `ext_capture.rs:666-692`: waits 2 s for a constraints batch that already arrived, on every resolution change.
  - After a mode switch there is no repeat source, so a static screen can time out three times and push the engine off ext and zero-copy.
  - The repeat deadline races fresh frames at source≈capture rate, causing judder.
  - The portal session is never closed on error paths.
  - StartRecording does file I/O on the daemon loop.
  - A save-thread panic leaves `busy` set forever.
  - Stopping a recording drops queued packets and the last ~200–300 ms of audio.
  - The microphone is never recorded in full recordings.
  - The keyframe is requested before the recording tap is installed.
  - A configure-job `JoinError` wedges the daemon.
  - SIGTERM is honoured only once.
  - The watchdog never triggers recovery (the docs say it does).
  - Startup falls through to the portal after a transient ext/wlr failure, which risks a picker dialog.

**Media capture and saves**

- **The AAC encoder hands swresample `frame->data` (8 pointers) instead of `extended_data`.** With more than 8 planar channels it writes through garbage pointers, a heap overwrite reachable from the safe `write_clip` and `Recorder::start` APIs. It is latent: the engine always passes 2 channels. Fix: use `extended_data`, or reject `channels > 8`. `crates/fthrust-media/src/ffi/aac.rs:179-185`. **verified**.
- **Reported, not re-checked:**
  - **Full-length saves anchor audio and the start keyframe on the request time, not the newest packet,** so audio leads video by the encoder's latency. That is up to 3 frames on NVENC and tens of frames with SVT-AV1 or aom lookahead. `ring.rs:226-265`, `save.rs:127-169`.
  - **A failed `renameat2` plus a failed hard-link fallback deletes the fully written `.partial`,** for example on FUSE without rename2. The clip is lost. `transactional_save.rs:136-160,237-239`.
  - **Disk-mode `pwrite` and `sync_file_range` run on the capture thread under the ring mutex,** so a save to the same disk can stall capture. `ring.rs:150-165`, `payload.rs:183-226`.
  - **Clips end on 20–50 ms of zero-padded silence,** because the save waits for video but not audio.
  - **QSV preset 7 maps to `slowest`,** which FFmpeg rejects. libkvazaar has no `preset` option (use `kvazaar-params`).
  - **`Recorder::start` failures leave an empty `FTHR_recording_*.mp4`.**
  - **Recordings are never fsynced.**
  - **The recorder writes dts = pts.**
  - **A failed `encode()` swallows a pending keyframe request.**
  - **Frame-size checks use unchecked arithmetic** (`encoder.rs:607`, `scaler.rs:98,106`, `vpp.rs:210`).
  - **`encoder_works` passes without producing a packet.**
- **Reported optimisations:**
  - Keep FFmpeg's packet buffer as the payload; this saves 2 copies and about 3 allocations per packet.
  - Encode AAC straight from the slice; this halves peak audio memory on long saves.
  - Add a single-generation fast path for `snapshot()`.
  - Create the two unused VA pools lazily, saving about 45 MB of VRAM at 4K.

**UI services**

- **Restart/apply requests are dropped while another is pending or deferred.** The first deferred config wins; while `restart_pending`, the call returns early. `crates/fthrust-ui/src/services/engine.rs:425-436`. **verified**.
- **The engine stderr reader stops at the first non-UTF-8 line.** The read end closes, and the engine's next `eprintln!` (engine.rs:232/253/263/306) panics with EPIPE, so the engine crashes and the buffer is lost. `startup-error` parsing and `engine.log` also stop. Use `read_until` plus `from_utf8_lossy`. `services/engine.rs:1019`. **verified**.
- **`pending_engine_events` is pushed and never drained** (hundreds of SaveProgress per save, kept for the whole session). `services/mod.rs:1013`, `state.rs:556`. **verified**.
- **Reported, not re-checked:**
  - A crashed or hung engine is never auto-restarted. After 3 s of silence only the status text changes, and saves are still admitted.
  - A save is accepted while the engine is stopping: a success card, then failure.
  - `engine_config` errors are swallowed in 3 of 4 callers, so the status shows "Starting capture" forever.
  - `spawn_engine` unlinks `engine.sock` unconditionally, and `EngineServer::drop` unlinks by path.
  - Blocking starts on the UI thread: MicLevel ≤3 s, SoundPlayer ≤5 s, ToplevelWatcher ≤5 s, with leaked threads on timeout.
  - The window isn't hidden during the ≤20 s `prepare_exit`.
  - Second-launch activation repaints a throwaway `egui::Context`.
  - `xdg-open` children are never reaped.
  - GlobalShortcuts calls after the first bind have no timeout.
  - Recording "Finalizing" has no timeout.

**Media, playback and export**

- **Each closed editor leaks its GPU video texture.** `free_texture` runs only on a size change; `editor_video = None` just drops it. That is 8 MB at 1080p and 33 MB at 4K per editor session. `crates/fthrust-ui/src/video_texture.rs:86-128`, `editor/sessions.rs:106,135`. **verified**.
- **Stream-copy trims with audio demux the whole rest of the file.** The `break` needs `copy_audio` empty, and skipped packets don't refresh `last_output`, so long recordings on slow storage hit the 120 s inactivity timeout. `crates/fthrust-media/src/export/run.rs:739-788`. **verified**.
- **Reported, not re-checked:**
  - `export::run` never checks the output duration, and finalize renames the result over the original clip (sink errors are swallowed).
  - The camera ring is capped by time only (90 s): 400–800 MB in the UI process at 1080p30 MJPEG.
  - Closing or parking the editor joins a decode worker mid-GOP: a 0.4–0.8 s UI stall.
  - Every pause re-seeks and re-decodes a GOP.
  - `Job::max_rate_kbps` is never read.
  - Export staging files are never reclaimed after a crash.

**Editor and library**

- **Reported, not re-checked:**
  - Export, Share and Ctrl+E before the player loads export a 1 ms range (`duration_ms = 1` placeholder).
  - Esc in the Share picker also closes the editor.
  - Library rename and delete ignore parked editor sessions and queued exports.
  - The trim-handle grab prefers Start when the handles are close.
  - Day-section labels have no year, so the same date in different years merges.

**Core**

- **Diagnostics are only half wired.**
  - Core's `init_logging` and `init_crash_log` are never called by the UI, so `fthr.log` and `fthr-crash.log` are never written.
  - `active-session.json` is written but never removed, so every launch reports the previous session as unclean.
  - The UI's `EnvFilter::from_default_env()` is ERROR-only without `RUST_LOG`.
  - The support ZIP reads `fthr.log` and a session `engine.log` that nothing writes.
  - **verified** (marker, init); rest reported.
- **Secrets are written world-readable.** `atomic_json` uses `File::create` (0666 & ~umask), so `~/.fthr/uploader/settings.json`, which holds `upload_auth_header` and `catbox_userhash`, ends up 0644 in a 0755 directory. Every save also resets any chmod. `crates/fthrust-core/src/atomic_json.rs:35`. **verified**.
- **Reported, not re-checked:**
  - An unreadable store is treated as empty and then overwritten. `settings.json` is saved at every exit, so a transient read failure replaces it with defaults.
  - Theme ZIP import has no total-size or entry-count cap (zip bomb), and deletes the old assets before writing the new ones.
  - egui key names (PageUp, Equals, Backtick, Quote, brackets…) aren't mapped to xkb keysyms, so Hyprland binds and portal triggers are invalid. The Lua writer only upper-cases.
  - `cleanup_stale_partials` has no caller and is too narrow, so crashed saves and recordings leak hidden `.partial` files.
  - Startup `exit(2)` when the migration save or theme dir creation fails (a full disk then blocks opening the app to delete clips).
  - The clip-metadata DB failure is retried every frame, with a log line each time.
  - Redaction gaps: `sftp_password=`, `client_secret=`, `upload_token=`, `userhash` in free text, multi-pair `Cookie`.
  - `events.jsonl` is re-redacted as text, which makes invalid JSON.
  - Editor open SHA-256s the whole clip twice.

**Uploader (non-tier-1)**

- **`tools/check-upload-isolation.sh` fails open.** `2>/dev/null … || true` means a `cargo tree` failure prints "upload isolation ok". The deny-list is also narrow (no hyper/rustls/h2). **verified**.
- **Reported, not re-checked:**
  - Auto-delete accepts any non-empty "url" (`queued`, `file:///…`, multi-line).
  - Success messages ("no link", "local delete failed") are dropped, leaving a dead share button.
  - Interval mode plus imported folders plus auto-delete uploads and deletes whole imported libraries (documented as intended; risky).
  - The SFTP host-key algorithm order is fixed with Ed25519 first, so ECDSA or RSA `known_hosts` entries read as untrusted.
  - Builder errors are retried as network errors.
  - `describe()` leaks URL query strings.
  - A non-UTF-8 `known_hosts` breaks SFTP trust.
  - A SIGKILL leaves `.part` files on SFTP servers.
  - The release binary honours `FTHRUST_UPLOADER_CATBOX_URL`.
  - SFTP throughput is capped near 512 KiB per RTT (16×32 KiB in flight).

## CI, build, release, repo

**Measured**

- **LTO.** Fat LTO with `codegen-units = 1` makes the release binaries a third smaller (combined 76.7 MB → 51.7 MB, −33%); the clean release build took 3m20s on 8 cores. Recommended:
  ```toml
  [profile.release]
  lto = "fat"
  codegen-units = 1
  strip = "debuginfo"
  ```
  | Binary | Default profile | With LTO |
  |---|---|---|
  | fthrust | 47.5 MB | 34.6 MB |
  | fthrust-engine | 12.0 MB | 7.0 MB |
  | fthrust-uploader | 17.3 MB | 10.2 MB |

  `panic = "abort"` is not an option: `catch_unwind` is used in the engine, export, finalize and upload. `strip = "symbols"` would save another ~7 MB but loses backtrace names.
- **AppImage size.** The 86 MB AppImage is mostly the BtbN all-libraries FFmpeg: libavcodec 69 MB, libavfilter 30 MB, libavformat 24 MB, libswscale 13 MB uncompressed. A trimmed FFmpeg build (the needed hw encoders, the h264/hevc/av1 decoders, aac, mjpeg, mp4/mov, v4l2) would cut most of it.

**CI** (verified unless marked)

- **The `check` job has no Rust cache,** and it `cargo install`s cargo-deny and cargo-about from source every run. There is no `concurrency`, and it runs on every push plus `pull_request`, so it runs twice for PR branches and again for tags. Add `Swatinem/rust-cache` and prebuilt tools (taiki-e/install-action); reported saving is ~15+ min per run.
- **Release isn't gated on CI.** A tag push publishes even if CI is red or still running (release.yml runs no fmt, clippy or tests). *(reported)*
- **Actions are pinned to tags or branches, not SHAs,** including in the release path. There is no `dependabot.yml`.
- **CI cargo commands lack `--locked`** (the release build has it).
- **CI tests against Ubuntu's FFmpeg 6.1 while the release ships BtbN 8.1.2.** *(reported)*
- **tools/uidrive is never fmt'd, linted or tested in CI.** No workflow has `timeout-minutes`.

- **Pedantic clippy highlights:**
