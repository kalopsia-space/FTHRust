# File and folder pickers: Python reference notes

Paths are relative to `reference/FTHR_UI/`. `main` = `main.py` (all pickers except the theme ones live in `_SettingsPage`, main:10012+), `cp` = `ui/customize_page.py`, `tm` = `core/theme_manager.py`, `sm_core` = `core/settings_manager.py`, `lo` = `core/library_ownership.py`. Line numbers are approximate to the line quoted. Every picker is a static `QFileDialog` call with the Qt-owned dialog (no custom dialog classes, no `Options` except `ShowDirsOnly`); on Linux Qt picks the xdg-desktop-portal or Qt widget dialog, nothing in the app depends on that.

Other `QFileDialog` uses, out of scope here: game folder/executable pickers (main:2414/2417, game-detection popup), `getSaveFileName` at main:3733 (save-as) and cp:1943 (Export Theme, section 11 cross reference).

## 1. Clips storage folder

- UI: Settings page, "Folders" section (main:11020). Row label `CLIPS STORAGE FOLDER`, read-only line edit `clips_directory_edit` (value from `_storage_path_for_display('clips_directory', clips_directory_from)`), button `BROWSE` (tooltip `Choose where FTHR stores clips, screenshots, exports, and shares.`), second button `USE DEFAULT` (tooltip `Use the platform default clips folder.`, handler `_on_clips_folder_use_default`, main:10708, calls `_commit_clips_directory(default_clips_directory())`).
- Call: `QFileDialog.getExistingDirectory(self, 'Select Clips Storage Folder', current, QFileDialog.Option.ShowDirsOnly)` (main:10699). Single directory.
- Start directory: `str(clips_directory_from(self.sm))` (settings key `clips_directory`, resolved: `os.path.expandvars` + `expanduser` + `resolve(strict=False)`, must be absolute). If that raises `StoragePathError`: start dir is `str(Path.home())` and `_report_storage_change_failure(error)` runs BEFORE the dialog opens (modal warning, below). The fallback start dir is never saved unless the user picks it.
- Cancel: returns. If the pre-dialog resolve had failed it also prints `[Storage] Clips folder selection cancelled: {error}`. No settings touched.
- Chosen path -> `_commit_clips_directory(folder)` (main:10727), which returns bool and does, in order:
  1. Reads the old `recording_directory` (missing sentinel). `recording_is_derived = True` if the key is missing or `None`; otherwise it is also treated as derived if `recording_directory_from(sm) == old_clips_root / 'Recordings'` (both resolve without error). Else the explicit recording path is preserved untouched.
  2. `new_root = prepare_clips_storage(directory, probe_writable=True)` (sm_core:122): resolve the path (`_resolve_storage_path(value, 'storage')`: empty/non-str/non-absolute -> `StoragePathError`), `mkdir(parents=True, exist_ok=True)`, check `is_dir()`, write-probe by `tempfile.mkstemp(prefix='.fthr-storage-probe-', dir=...)` then unlink; then the same for each of the five subfolders `Desktop`, `Recordings`, `Exported`, `Shared`, `Screenshots`. Any `OSError` becomes `StoragePathError('FTHR cannot use the storage folder "{resolved}". Choose a writable folder in Settings. No files were moved. ({exc})')`.
  3. Snapshots the previous `clips_directory`/`recording_directory` entries from `sm.settings` (present flag + value) for rollback.
  4. `sm.set('clips_directory', str(new_root))`; `sm.set('recording_directory', str(new_root/'Recordings'))` when derived, else the preserved old value.
  5. `sm.save_settings()`; if it returns falsy: restores (or pops) the two keys in the dict and reports `StoragePathError('FTHR could not save the new storage location. Your current library remains selected; choose a writable settings folder and try again. No files were moved.')`; returns `False`.
  6. Catches `(OSError, TypeError, ValueError)`: reports the `StoragePathError` as is, else `StoragePathError('FTHR could not use the selected storage folder. Choose a valid writable folder in Settings. No files were moved.')`; returns `False`.
  7. On success: `clips_directory_edit.setText(str(new_root))`; if derived and `recording_directory_edit` exists, sets it to `str(new_recording)`; emits `clips_directory_changed(str)`; returns `True`.
- `_report_storage_change_failure(error)` (main:10728): `emit_event('storage', 'directory_change_failed', state='FAILED', detail=str(error))` then `FthrMessageDialog.warning(self, 'Storage location unavailable', str(error))` (modal). No error bar.
- Signal wiring (main:4049): `clips_directory_changed` -> `self.clip_grid.set_clips_directory(path, prepared=True)` (ui/clip_grid.py:3013). With `prepared=True`: path must be a non-empty absolute string without NUL, else `_report_storage_unavailable(StoragePathError('The prepared clips storage folder must be a non-empty absolute path without NUL characters.' / 'The prepared clips storage folder is invalid.'))`; no second probe. If equal to the current `clips_dir` it just calls `force_refresh()`. Otherwise: cancels any running transition animation, removes watcher paths under the old root, sets `clips_dir`, clears `_storage_error_reported`, `_known_files`, `_imported_files`, adds the new root to the `QFileSystemWatcher`, calls `_load_clips()` (full rescan).
- NOT done: no files are moved or copied from the old root, no capture-engine restart, no capture-card restart. The new root is used by the next save/export/screenshot because every consumer re-reads `clips_directory_from(sm)`.
- Linux: `default_clips_directory()` (sm_core:25) has no platform branch: it calls `_windows_videos_directory()` (Qt `QStandardPaths.MoviesLocation`, normally `~/Videos` on Linux), requires an absolute result and returns `{Videos}/FTHR Clips`; an empty/relative result raises `StoragePathError` with the message text mentioning the Windows Videos folder (`FTHR could not locate the Windows Videos folder. Check that the Videos known folder is available, or choose a storage folder in Settings. No files were moved.`). Existing configs (config file present) default to the legacy root `~/FTHR_Clips` (sm_core:21, `_load_settings`).

## 2. Manual recording folder

- UI: row `MANUAL RECORDING FOLDER`, tooltip `Choose where manual recordings are written.`, read-only edit `recording_directory_edit`, `BROWSE` only (no `USE DEFAULT`, `default_slot` is None; main:11031).
- Call: `QFileDialog.getExistingDirectory(self, 'Select Manual Recording Folder', current, QFileDialog.Option.ShowDirsOnly)` (main:10805). Single directory.
- Start directory: `str(recording_directory_from(sm))` = `recording_directory` setting if set (and non-None), else `{clips root}/Recordings`. On `StoragePathError`: `Path.home()` and `_report_storage_change_failure(error)` before opening (same modal as section 1).
- Cancel: returns; prints `[Storage] Recording folder selection cancelled: {error}` only if the pre-resolve had failed.
- Chosen path:
  1. `resolved = str(ensure_storage_directory(folder, probe_writable=True))` (mkdir -p + write probe, sm_core:103). Failure -> `_report_storage_change_failure(error)` (title `Storage location unavailable`, message `FTHR cannot use the storage folder "{resolved}". Choose a writable folder in Settings. No files were moved. ({exc})`), return. Note: this does NOT create the five library subfolders.
  2. `owned_root = clips_directory_from(sm)` (None on `StoragePathError`).
  3. Snapshots `recording_directory` and `imported_clip_folders` for rollback, then `sm.set('recording_directory', resolved)`.
  4. If `resolved` is NOT inside `owned_root` (`Path.relative_to` raises `ValueError`, or the root is unavailable): `roots = add_import_root(sm.get('imported_clip_folders', []), resolved)` (lo:73: resolves every entry, appends only if the case/normpath key is not already present) and `sm.set('imported_clip_folders', roots)`. Rationale in comment: external recording directories are linked into the library so recordings stay editable after restart. If inside the clips root, imported folders are not touched.
  5. `sm.save_settings()` falsy -> restores/pops both keys, `_report_storage_change_failure(StoragePathError('FTHR could not save the manual recording folder. Your current folder remains selected. No files were moved.'))`, return (edit not updated).
  6. Success: if import roots changed -> `_refresh_import_folders_list()` and emit `imported_folders_changed` (-> `clip_grid.force_refresh`, main:4052); then `recording_directory_edit.setText(resolved)`.
- No restart of capture or recorder. The path is read at record start: main:6373 `target_dir = recording_directory_from(sm)`, then `mkdir(parents=True, exist_ok=True)` and `shutil.disk_usage`; failure there shows `push_error('RECORDING FOLDER UNAVAILABLE', str(exc), level='error')`.
- Changing the clips storage folder (section 1) rewrites `recording_directory` only when it was derived.

## 3. Import clip folder ("Add folder")

- UI: "Import Clips" section (main:11041): buttons `Add folder` (`button_outline_qss`) and `Scan for clips` (separate scan flow, `_on_import_folder_scan`, main:10854, not a picker). Below: list of linked folders, each row with a `close.png` button (tooltip `Remove this folder`, `_remove_import_folder`, main:10655) and a label; a missing directory shows `{path}  —  MISSING (remove link or reconnect drive)`.
- Call: `QFileDialog.getExistingDirectory(self, 'Select Clips Folder', str(Path.home() / 'Videos'), QFileDialog.Option.ShowDirsOnly)` (main:10669). Single directory. Start dir is always `~/Videos` (not the last import dir). Linux: `~/Videos` may not exist; Qt falls back to a parent.
- Cancel / `sm is None`: returns silently.
- Validation: none (no existence, readability, duplicate-with-clips-root or nested-folder checks). The only dedupe is `add_import_root`: all existing entries are re-resolved to absolute strings and the new path is appended only if its `os.path.normcase(normpath(resolved))` key is not already present. Duplicates are silently ignored (no message).
- On success: `sm.set('imported_clip_folders', folders)`; `sm.save_settings()` (return value ignored); `_refresh_import_folders_list()`; drop any pending scan result whose path equals the chosen folder (`self._scan_pending = [(n,p) for n,p in self._scan_pending if p != folder]`, compared against the raw dialog string) and `_rebuild_scan_results()`; emit `imported_folders_changed` -> `clip_grid.force_refresh()` (clears `_known_files`, `_load_clips()`; if the grid's background is paused it only sets `_background_refresh_pending`).
- Removal (`remove_import_root`, lo:84) rewrites the list, saves, refreshes the list, emits the same signal. Imported media is classed `LINKED_IMPORTED` by `classify_media_path` (lo:41, checked before the owned root) so it is protected from delete. Readers of `imported_clip_folders`: clip_grid.py:2043/2113/2175, clip_viewer.py:8459, upload_manager.py:511.
- No error bar or dialog on any path.

## 4. Gary Mode image

- UI: Gary Mode block in the Settings audio/mic area (main:11360): checkbox `Enable Gary Mode`, button `Choose` (object name `garyImageButton`, main:11372), button `Default` (`_reset_gary_image`), 'gary_preview' label.
- Call: `QFileDialog.getOpenFileName(self, 'Choose Gary Mode image', start, 'Images (*.png *.jpg *.jpeg *.webp *.bmp *.gif);;All files (*.*)')` (main:12687). Single file.
- Start directory: `self.gary_image_path or str(Path.home())`. Note this passes the previous FILE path as the start; Qt then opens its folder and preselects the file. Initial `gary_image_path` comes from setting `gary_image_path` (default `None`).
- Cancel: returns, nothing changed.
- Validation: `QPixmap(path).isNull()` -> `FthrMessageDialog.warning(self, 'Image not supported', 'Choose a valid PNG, JPG, WEBP, BMP, or GIF image.')` (modal) and return without saving. This is the only check; extension filter is advisory because "All files" is offered.
- On success: `self.gary_image_path = path`; `_refresh_gary_preview()` (loads `_effective_gary_image_path()`: the chosen file if `is_file()`, otherwise the bundled `assets/gary.png`; scales to `gary_preview.size() - QSize(8, 8)` with `KeepAspectRatio` + `SmoothTransformation`; on null pixmap shows text `No image`; tooltip is the effective path); `_save_gary_settings()` (main:12654): `sm.update({'gary_mode_enabled': checked, 'gary_min_level': low, 'gary_max_level': high, 'gary_image_path': path})` (thresholds clamped via `clamp_thresholds`), `sm.save_settings()`, emit `gary_settings_changed`.
- `gary_settings_changed` -> `MainWindow._sync_gary_settings` (connected main:3602; default arg `restart_recorder=True`): reloads enabled/thresholds, `self._gary_overlay.set_image(sm.get('gary_image_path'))`, and if Gary is enabled and `audio_capture_enabled` is true it (re)starts the mic recorder (Windows: stops/starts the Gary mic recorder; Linux: `_start_mic_recorder()` only when the legacy recorder is not already running); otherwise resets `_gary_current_intensity` to 0. So picking an image does a mic recorder restart as a side effect. No capture-engine restart.
- `Default` button: `gary_image_path = None`, refresh preview, `_save_gary_settings()`. A saved path that no longer exists silently falls back to the bundled image in the preview.

## 5. Image overlay layers ("Add images")

- UI: "Image Overlay" panel of the unified overlay editor (main:13050): button `Add images` (`button_primary_qss`, min height 36, main:13058) plus `Remove`, `Clear`, selector combo (items `{n:02d}  ·  {filename}`, or `No image layers` when empty), count label `{n} IMAGE LAYER(S)`, fit combo, opacity slider. The checkbox `image_overlay_check` is the enable toggle. A legacy duplicate panel (main:13380: checkbox `Burn an image into clips`, read-only edit placeholder `No image selected`, button `Choose image`, `Clear`) wires to the same `_choose_image_overlay`, but nothing ever updates its `image_overlay_path` edit after a pick; treat it as dead UI and do not port it.
- Call: `QFileDialog.getOpenFileNames(self, 'Add image overlays', start, 'Images (*.png *.jpg *.jpeg *.webp *.bmp);;All files (*)')` (main:11988). Multi-select. Note: no `.gif` here (unlike Gary and preview background).
- Start directory: parent folder of the FIRST stored layer's path (`layers[0]['path']`), else `Path.home()`.
- Cancel (empty list) -> returns `False`.
- Validation: `valid_paths = [p for p in paths if not QPixmap(p).isNull()]`; unreadable ones are silently dropped (no message). If none valid -> returns `False`, no message.
- On success: for each valid path `layers.append(new_image_overlay_layer(path, len(layers)))` (index at append time, so successive layers get distinct default rects/z); `_save_image_layers(layers)` (main:11927): `sm.set('image_overlays', layers)`; first layer mirrors to legacy keys `image_overlay_path`, `image_overlay_opacity` (int, default 100), `image_overlay_fit` (default `'fit'`), `image_overlay_rect` (`clamp_overlay_rect(first.rect, DEFAULT_IMAGE_OVERLAY_RECT)`); empty list sets `image_overlay_path=''` and `image_overlay_enabled=False`; `save_settings()`. Then `sm.set('image_overlay_enabled', True)`, `save_settings()`, `image_overlay_check` set checked with signals blocked, `_refresh_image_overlay_controls(len(layers)-1)` (selects the last added layer, repopulates selector, count label, fit, opacity, and pushes `unified_overlay_editor.set_image_layers(image_overlay_layers(sm))` + `set_selected_image`). Returns `True`.
- Enable-toggle path (`_on_image_overlay_toggled`, main:11890): turning it ON with no stored layers opens this same picker; if it returns `False` the checkbox is reset to unchecked (signals blocked) and `image_overlay_enabled` is saved as `False`. Stored layers come from `sm['image_overlays']` if a list, else `image_overlay_layers(sm)` (migrates legacy `image_overlay_path`, settings_manager.py:382). The toggle also calls `unified_overlay_editor.set_overlay_enabled('image', checked)`.
- No restart, no error bar. Layers are consumed at clip save: `_apply_image_overlay` (main:8057) returns if `image_overlay_enabled` is False, keeps only `layer.get('enabled')` layers whose `os.path.isfile(layer['path'])` is true (missing files are skipped; `select_post_route` also treats `image_overlay_enabled` like `camera_enabled`, main:7135, forcing the overlay post-process route).
- Remove/Clear: `_remove_selected_image_overlay`, `_clear_image_overlay` -> `_save_image_layers`, checkbox set to `bool(layers)`.

## 7. Theme archive import

- UI: Customize page action bar (cp:1511): `Export theme` (secondary), `Import theme` (outline), `Reset all`, Apply button; info bar text `Themes include typography, colors, icons, capture-card styling, and sounds  —  Fonts: .ttf, .otf  |  Icons: .png, .jpg, .jpeg, .bmp, .ico, .svg  |  Sounds: .mp3, .wav, .ogg, .flac, .m4a, .wma, .aac`.
- Call: `QFileDialog.getOpenFileName(self, 'Import Theme', '', 'ZIP files (*.zip)')` (cp:1959). Single file, start directory empty string (Qt default / last used dir on Linux the process cwd or portal default).
- Cancel -> returns.
- Confirmation: `_fthr_message_box(self, 'Import Theme', 'This will fully replace your current theme (typography, colors, icons, and sounds).\n\nContinue?')` (OK/Cancel, custom frameless QDialog, `ok_cancel=True` default). Cancel -> returns, nothing changed.
- `ThemeManager.import_theme(Path(src))` (tm:540) returns bool, `False` on any failure with ONLY a console `print`, no dialog (`[Theme] Invalid theme ZIP: missing theme.json`, `[Theme] Invalid theme.json: not an object`, `[Theme] Invalid theme.json: "{key}" is not an object`, `[Theme] Import failed: {e}`). In the page handler `if ok:` is the only branch, so a failed import shows NOTHING to the user. Validation order, all before touching the existing theme: zip opens (`zipfile.ZipFile`; `BadZipFile` -> generic failure); `theme.json` in names; JSON object; the keys `colors`, `icons`, `sounds`, `icon_tints`, `capture_card`, `fonts`, `font_files` must each be dicts if present; every `icons/`, `sounds/`, `fonts/` entry is read into memory first (keyed by `Path(name).name`, so path traversal is flattened).
- Then: wipes every file in `icons_dir`, `sounds_dir`, `fonts_dir` (`~/.fthr/theme/{icons,sounds,fonts}`), writes the new assets, rebuilds `_data` = `{palette_version: 4, typography_version: 2, colors: DEFAULT_COLORS + zip colors, icons, sounds, icon_tints (default {'_global': DEFAULT_ICON_TINT}), capture_card: DEFAULT_CAPTURE_CARD_COLORS + zip, fonts: DEFAULT_FONTS + zip, font_files}`. Font roles whose family is neither built-in (`Oswald`, `Segoe UI`) nor listed in `font_files` are reset to `Oswald`. Calls `self.save()` (atomic `.json.tmp` + `os.replace`). Not transactional after the wipe: a write error mid-way leaves a wiped theme.
- On success: `_refresh_all()` (cp:1996: re-registers custom fonts via `QFontDatabase.addApplicationFont`, rebuilds the font combos from built-ins + `get_custom_font_paths()`, repairs invalid roles to `DEFAULT_FONTS`, refreshes swatches/icons/sounds rows), then `_fthr_message_box(self, 'Imported', 'Theme imported successfully.\nClick APPLY THEME to see changes in the app.', ok_cancel=False)`. The app stylesheet/fonts are NOT re-applied until the user presses Apply -> `theme_applied` -> `_SettingsPage._on_theme_applied` (main:13499: `Fonts.configure(...)`, patch `Colors`, `apply_app_style`, restyle all top levels, `customize_page.refresh_theme()`, `top._apply_theme()`).
- Export counterpart for reference: `getSaveFileName(self, 'Export Theme', ~/fthr_theme.zip, 'ZIP files (*.zip)')`, success box `Exported` / `Theme exported to:\n{dest}`; failure silent (print only).

## 8. Custom font file (display / body roles)

- UI: Typography section (cp:1555). Two rows, role `display` titled `Heading font` and role `body` titled `Interface font`, each with a combo (built-ins `Oswald`, `Segoe UI` then custom families sorted case-insensitively) and a button `Import font` (`button_outline_qss`) bound with the role. Below: preview label `Your privacy isn't currency.` and `Reset typography`.
- Call: `QFileDialog.getOpenFileName(self, 'Import font', '', 'Font files (*.ttf *.otf)')` (cp:1625). Single file, empty start dir.
- Cancel -> returns.
- Validation: `font_id = QFontDatabase.addApplicationFont(file_path)`; `families = applicationFontFamilies(font_id)` if `font_id >= 0`. Empty -> `_fthr_message_box(self, 'Font not supported', 'Choose a valid OpenType (.otf) or TrueType (.ttf) font file.', ok_cancel=False)`, return. (Because the filter is advisory, any other file Qt happens to load, e.g. .woff or .pfb, passes this step and is then rejected at the next one.)
- `self._theme.set_custom_font(list(families), Path(file_path))` (tm:485): raises `ValueError('Only .ttf and .otf font files are supported')` if suffix (lowercased) is not .ttf/.otf; `ValueError('The font does not expose a usable family name')` if all family names are blank; copies the file with `shutil.copy2` to `~/.fthr/theme/fonts/{source.name}` (same name overwrites); records `font_files[family] = dest.name` for EVERY family in the file. Then `theme.save()`. `except (OSError, ValueError) as exc` -> `_fthr_message_box(self, 'Font import failed', str(exc), ok_cancel=False)`, return (the font stays registered in Qt for the session).
- Success: every font combo (both roles) gets each new family added if `findData(family) < 0` (item text and data = family); then the combo of the clicked role selects `families[0]` — NOT with blocked signals, so `currentIndexChanged` fires `_on_font_changed(role)`: `theme.set_font(role, combo.currentData())`, `theme.save()`, `_update_font_preview()`. The other role is not changed. No success dialog. The font is applied app-wide only after `APPLY THEME` (`Fonts.configure` in `_on_theme_applied`). At next startup custom fonts are re-registered from `get_custom_font_paths()` (existing files only; stale entries excluded).
- `Reset typography` -> `theme.reset_fonts()` (roles back to `Oswald`, imported files stay in `font_files`/disk), save, combos reset with signals blocked.
- Linux: `Segoe UI` is a built-in family name but is not shipped; the body font fallback list in `capture_card._body_font` is `[family, 'Segoe UI', 'Noto Sans', 'DejaVu Sans']`.

## 9. Custom icon file

- UI: Icons section (cp:~1740-1766): one `_IconRow` per customizable icon (`self._filename` e.g. `close.png`, `self._label`), showing `Default:` and `Current:` 28px thumbnails and buttons `Import` and `Reset`.
- Call: `QFileDialog.getOpenFileName(self, f'Select icon for {label}', '', f'Images ({formats})')` where `formats` = `*.png *.jpg *.jpeg *.bmp *.ico *.svg` (cp:1008). Single file, empty start dir, no All-files entry.
- Cancel -> returns.
- Steps and validation, in order:
  1. `file_size_kb = source.stat().st_size / 1024` (an `OSError` here is NOT caught and would propagate out of the slot).
  2. `target_size = max(ref_w, ref_h, 32)` from the bundled default icon (`_default_icon_path(filename)`; falls back to a 32x32 pixmap if missing).
  3. `QPixmap(str(source))` null -> silent return (no message; so e.g. an unreadable .svg/.ico is ignored).
  4. If `file_size_kb > 100`: `_fthr_message_box(self, 'Large Icon File', f'This image is {kb:.0f} KB.\n\nIcons larger than 100 KB may slightly impact startup time and memory usage. The icon will be resized to {target}x{target}px which reduces the stored size.')` (OK/Cancel); Cancel -> return.
  5. Always shows the crop dialog `_show_crop_dialog` (cp:1061): frameless `QDialog` min 500x400, custom title `Crop Icon — {label}`, `_IconCropWidget` plus a 64px `Reference` column showing the default icon, standard `Ok`/`Cancel` button box. Cancel -> `None` -> return.
  6. Result is saved as PNG to `{icons_dir}/_temp_{filename}` (`final.save(path, 'PNG')`); failure -> `print('[Theme] Failed to write temp icon for {filename}')` and return silently.
  7. `theme.set_custom_icon(filename, temp)` (tm:383): dest name is `Path(filename).stem + temp.suffix.lower()` (so always `.png`, replacing `close.png`-style names) in `~/.fthr/theme/icons`, `shutil.copy2`, `_data['icons'][filename] = dest_name`. Temp file then unlinked, `theme.save()`.
  8. `_load_current_icon()` refreshes the `Current:` thumbnail (custom path if it exists else default); emits `icon_changed(filename)` whose handler is a no-op (`pass`, comment: icons apply on next app restart or when Apply is clicked).
- `Reset`: `theme.remove_custom_icon(filename)` (pops key, deletes file), save, reload thumbnail, emit `icon_changed`.

## 10. Custom sound file

- UI: Sounds & Volumes section (cp:1920), one `_SoundRow` (fixed height 52) per key of `CUSTOMIZABLE_SOUNDS`: `clip_captured` "Clip Captured", `screenshot_captured` "Screenshot Captured", `error` "Error", `startup` "Startup", `upload_successful` "Upload Successful", `upload_failed` "Upload Failed". Each row: file label (`(default)` or `{name} ({size_kb:.0f} KB)`), volume slider 0-100 (setting `sound_volume_{clip|screenshot|error|startup|upload_successful|upload_failed}`, default 100), `preview` button, `Import`, `Reset`.
- Call: `QFileDialog.getOpenFileName(self, f'Select sound for {label}', '', f'Audio files ({formats})')` with `formats` = `*.mp3 *.wav *.ogg *.flac *.m4a *.wma *.aac` (cp:1389). Single file, empty start dir, no All-files entry.
- Cancel -> returns.
- Validation: none (no decode test, no size limit, no extension re-check).
- On success: `self._sound_playback.stop()`; `stored = theme.set_custom_sound(key, Path(file))` (tm:409: dest `{key}{suffix.lower()}` in `~/.fthr/theme/sounds`, `shutil.copy2`, `_data['sounds'][key] = dest_name`; an `OSError` from the copy is NOT caught); `theme.save()`; `_update_file_label()`; `self._sound_playback.prepare(stored)` (pre-decodes/loads into the row's `SoundPlayback`); emit `sound_changed(key)` (handler `_on_sound_changed` is `pass`: "Sounds apply immediately (next time the event fires)"). No dialog.
- Runtime lookup: `capture_card._resolve_sound(key)` (ui/capture_card.py:82) calls `ThemeManager().get_custom_sound_path(key)` each time and falls back to the bundled cue on any missing/corrupt file.
- `Reset`: `theme.remove_custom_sound(key)` (pops key, deletes file), save, update label, `sound_playback.stop()`, emit `sound_changed`. `Reset all` also sets every `sound_volume_*` setting to 100.
- Bundled defaults: `assets/sounds/{clip_captured,error,screenshot_saved,startup,upload_successful,upload_failed}.wav` (`screenshot_captured` maps to `screenshot_saved.wav`).

## 11. Cross-cutting notes for the port

- Message surfaces used: modal `FthrMessageDialog.warning(parent, title, text)` for storage and Gary image errors; the Customize page's own frameless `_fthr_message_box(parent, title, message, ok_cancel=True)` returning bool for theme/font/icon. No `push_error` error bar is used by any picker (the only error bar nearby is `RECORDING FOLDER UNAVAILABLE` at record time).
- Silent failures worth deciding on: import-folder (no validation), image-overlay (unreadable files skipped without message), preview background (unreadable ignored), icon (null pixmap, temp write failure), sound (no validation), and theme import (every failure is console-only). The reference gives no user feedback in these cases.
- Settings keys written by pickers: `clips_directory`, `recording_directory`, `imported_clip_folders`, `gary_image_path` (plus `gary_mode_enabled`, `gary_min_level`, `gary_max_level` rewritten alongside), `image_overlays`, `image_overlay_path`, `image_overlay_opacity`, `image_overlay_fit`, `image_overlay_rect`, `image_overlay_enabled`, `input_overlay_preview_background`. Theme pickers write `~/.fthr/theme/theme.json` (not `settings.json`) plus copied assets under `~/.fthr/theme/{icons,sounds,fonts}`.
- Storage rollback pattern (1 and 2): snapshot `(present, value)` for each touched key, set, `save_settings()`, and on a falsy return restore or pop each key directly in `sm.settings` and show the modal. `sm.save_settings()` returns bool for these keys.
- Linux specifics: no platform branches exist in the picker code itself; start dirs are `~` or `~/Videos`; empty start dir `''` is used by the theme/font/icon/sound pickers (Qt picks last used / cwd). `os.path.expandvars` is applied to configured storage paths. `Applications (*)` / `Executables (*.exe)` filter branching exists only in the game-picker (not covered).
